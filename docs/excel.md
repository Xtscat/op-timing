# Excel 报表设计说明（`report.xlsx`）

本文档描述聚合报告工作簿（`<trace>.report.xlsx`）的结构、字段口径与阅读方法。数值与同名 `report.json` 完全一致，两者由 `tools/op-timing-report.py` 一次生成。

工作簿的设计目标为提供直接、清晰的阅读体验：表头采用标准中文并附指标解释页，占比列直接呈现计算结论，时间列采用固定小数位格式避免科学计数法。

---

## 1. 定位与生成

- 每次执行分析脚本同时产出两份等值产物：`<trace>.report.json` 面向自动化指标提取，`<trace>.report.xlsx` 面向人工浏览与评审汇报。
- 生成命令无选项、无额外参数：

  ```bash
  python3 tools/op-timing-report.py /tmp/op_trace.json
  # /tmp/op_trace.report.json  ← 机器可读聚合报告
  # /tmp/op_trace.report.xlsx  ← 本工作簿
  ```

  两个产物固定写在追踪文件同目录、同基名下。

## 2. 文件格式实现

工作簿是标准 Office Open XML（SpreadsheetML）文件，由 Python 标准库 `zipfile` 直接写入，不依赖 `openpyxl` 等第三方库。

| 压缩包条目 | 职责 |
| --- | --- |
| `[Content_Types].xml` | 内容类型声明 |
| `_rels/.rels` | 根关系，指向工作簿 |
| `xl/workbook.xml` | 工作表清单：`总览`、`Pass`、`算子`、`算子×动作`、`说明`（共 5 个） |
| `xl/_rels/workbook.xml.rels` | 工作表与样式部件的关系 |
| `xl/styles.xml` | 字体、数字格式与单元格样式 |
| `xl/worksheets/sheet1.xml` … `sheet5.xml` | 各工作表数据 |

编码规则：

- 数值单元格写入 `<v>`（真数值，可直接参与求和、排序与数据透视）；字符串单元格以 `t="inlineStr"` 写入。
- 浮点数以十进制定点写入（`0.000009` 而非 `9e-06`），与显示格式一致。
- 特殊字符经 `xml.sax.saxutils.escape` 转义；XML 非法控制字符（U+0000–U+001F 中除制表符、换行、回车以外）自文本中剔除，避免产出损坏的工作簿。

呈现规则：

| 规则 | 目的 |
| --- | --- |
| 首行表头加粗并冻结（`pane ySplit="1"`） | 向下翻页时列名始终可见 |
| 三张明细表启用自动筛选（`autoFilter`） | 7000 行级表格可按任意列过滤、排序 |
| 列宽按该列最宽内容自适应，取值区间 `min(max(最宽 + 2, 9), 48)` | 避免长 C++ 类型名过度挤占显示区域，同时兼顾紧凑性 |
| 时间列固定 6 位小数（`0.000000`） | 与采集分辨率 1 µs 严格对应，避免呈现 `5E-06` 等科学计数法形式 |
| 次数列千分位（`#,##0`） | 大计数易读 |
| 占比列百分比格式（`0.00%`），单元格内保存 0–1 的小数 | 数值可继续参与运算，同时显示带符号 |
| 明细表超过 100,000 行时截断，表末一行注明总数 | 工作表最多 1048576 行，且百万行级别无法阅读；完整数据始终在 `report.json` 中 |

## 3. 工作表与列定义

### 3.1 `总览`

只有三块内容：总耗时，最慢的 5 个 Pass，最慢的 5 个算子。

| 区块 | 内容 |
| --- | --- |
| 总耗时 | `total_s`：追踪内首个事件到最后一个事件的时间跨度 |
| 最慢的 5 个 Pass | 排名、Pass、次数、自耗时、占比 |
| 最慢的 5 个算子 | 排名、算子、次数、自耗时、占比 |

展开细节在 `Pass` / `算子` / `算子×动作` 三张表；耗时构成、无动作区间这类诊断信息只在控制台打印，不进入工作簿，理由与口径见 `docs/measurement.md` 第 1.4 节。

### 3.2 `Pass`

Pass 级性能分布，含动作之外的框架耗时。仅收录 `pass-execution` 与 `greedy-iteration`，行按 `self` 降序排列。

| 列 | 单位 | 含义 |
| --- | --- | --- |
| `#` | — | 排名，1 为最慢 |
| `Pass` | — | `pass: ` + Pass 名，或 `greedy-iteration` |
| `选项` | — | Pass 对应的命令行选项名（如 `canonicalize`），用于映射回编译管线配置 |
| `类型` | — | `Pass` / `嵌套管线汇总` / `Pattern` / `贪心` |
| `次数` | 次 | 执行次数 |
| `自耗时 (s)` | s | 自耗时之和：区间耗时扣除直接子动作后的净值累计 |
| `占比` | % | 该行 `self` 占分母的比例，分母见 3.1 的「占比分母」 |
| `含子区间 (s)` | s | 区间起止总耗时累计（含嵌套子动作），不可跨行相加 |
| `单次最大 (s)` | s | 单次最大 `self` |
| `平均 (s)` | s | `self / 次数` |
| `动作外 (s)` | s | 该动作 `E` 事件至同线程下一事件的时间间隔，对应 Pass 后的 IR 验证与分析失效（`--verify-each=false` 可将其消除） |

### 3.3 `算子`

改写类动作（`apply-pattern`）在具体 Operation 实例上的开销分布。贪心重写驱动循环与自定义 Tag 不进入本表，行按 `self` 降序排列。

| 列 | 单位 | 含义 |
| --- | --- | --- |
| `#` | — | 排名 |
| `算子` | — | Operation 类型名，例如 `arith.constant` |
| `符号名` | — | Operation 的符号名（`sym_name`），例如函数名；无符号时为 `-` |
| `文件` / `行` | — | 源码位置拆成两列：`file:line:col` 中的文件与行号，便于筛选与排序 |
| `次数` | 次 | 改写触发次数 |
| `自耗时 (s)` | s | 同 3.2 |
| `占比` | % | 同 3.2 |
| `含子区间 (s)` | s | 同 3.2 |
| `单次最大 (s)` | s | 同 3.2 |
| `平均 (s)` | s | 同 3.2 |

### 3.4 `算子×动作`

全部动作（Pass 执行、贪心重写驱动循环、具体改写动作、自定义 Tag）的全集视图，聚合键为 `(op, scope)`。

| 列 | 单位 | 含义 |
| --- | --- | --- |
| `#` | — | 排名 |
| `算子` | — | 动作作用的 Operation 类型名 |
| `算子合计 (s)` | s | 同一算子在全部动作下的 `self` 合计，避免靠观察相邻行推断分组 |
| `动作类型` | — | `Pass` / `嵌套管线汇总` / `Pattern` / `贪心` |
| `动作` | — | 简名：去除命名空间、`{anonymous}` 标记与模板实参后的基础标识符（如 `AdjustSubFuncArguments`） |
| `次数` | 次 | 动作触发次数 |
| `自耗时 (s)` | s | 同 3.2 |
| `占比` | % | 同 3.2 |
| `含子区间 (s)` | s | 同 3.2 |
| `单次最大 (s)` | s | 同 3.2 |
| `平均 (s)` | s | 同 3.2 |

排序契约：同一 `算子` 的所有行相邻排列；组间按 `self` 总和降序，组内按 `self` 降序，并列时按 `(op, scope)` 字典序。源码行级归因由 `算子` 表承担，本表不携带 `loc`。

`动作` 列取值的清洗规则（`short_name`，见 `tools/op-timing-report.py`）：

1. 去掉 `pass: ` 前缀；
2. 去掉 `(anonymous namespace)::` 与 `{anonymous}::`；
3. 递归去除模板实参（`ConstrainedVectorConvertToLLVMPattern<mlir::arith::TruncFOp, …>` → `ConstrainedVectorConvertToLLVMPattern`）；
4. 取最后一个 `::` 之后的部分。

真实追踪中 Pattern 名平均长度 39 字符、最长超过 130 字符，其中 85/266 含 `{anonymous}` 标记，直接完整展示不利于快速浏览，故仅展示简名；追踪记录的原始名称保留在 `report.json` 的 `per_scope` 段。

### 3.5 `说明`

指标字典，四列：`列名` / `含义` / `单位` / `说明`，共 13 条：`self`、`incl`、`worst`、平均、次数、`outside`、占比、动作类型、动作简名的清洗规则、算子合计、时间列小数位、空值 `-`、截断提示。本表内容与 `docs/usage.md` 第 3 节保持一致。

## 4. 指标计算口径

1. **区间配对**：`analyse()`（`tools/op-timing-report.py`）按线程（`tid`）维护调用栈，把 `B`/`E` 配对为区间，`duration = E.ts - B.ts`。
2. **自耗时**：`self = max(duration - child, 0)`，子区间时长并入其直接父区间。
3. **完整事件**（`ph = "X"`）：`duration = dur`，`self = dur`；与父区间重叠的部分从父区间 `child` 中扣除，因此父子的 `self` 不会重复计算同一段时间。
4. **聚合**：按聚合键累计 `count`、`self`、`incl`，`worst` 取单次最大 `self`。
5. **动作之外耗时**：Pass 区间的 `E` 之后、同线程下一事件之前的间隔；按事件在文件中的先后位置定位下一事件，因此两个区间在同一时间戳闭合时该间隔为 0。
6. **无动作区间**：同一线程上「不在任何动作区间内」的时段，由事件流的嵌套深度判定。它与 `outside` 互相穿插（`outside` 只覆盖 Pass 结束到下一事件这一段），只在控制台的「耗时构成」中标示，不进入工作簿。

单位约定：所有时间字段均为秒（s）。原始追踪事件的时间戳为整数微秒（`docs/trace-format.md`），脚本在聚合边界换算；1 s = 1,000,000 µs。

求和规则：

- `self` 可跨行求和，无重复计数；全表 `self` 之和等于 `inside_actions_s`。
- `incl` 不可跨行求和——父区间包含子区间，跨行求和将导致重复计数。

## 5. 计算示例

设动作 A 区间为 [0, 30)，其内部包含动作 B 区间 [10, 20)：

| 动作 | `duration` | 直接子动作合计 | `self` | `incl` |
| --- | --- | --- | --- | --- |
| A | 30 | 10 | 20 | 30 |
| B | 10 | 0 | 10 | 10 |

`self` 合计 = 20 + 10 = 30，等于覆盖区间总长；`incl` 合计 = 30 + 10 = 40，其中 10 被重复计数。这解释了第 4 节求和规则的依据。

## 6. 阅读指南

推荐按 `总览` → `Pass` → `算子×动作` → `算子` 的顺序逐层下钻：

1. `总览`：确认总耗时与最慢的 5 个 Pass / 5 个算子，判断要不要继续下钻；
2. `Pass`：筛选 `类型 = Pass` 定位慢阶段，对比「自耗时」与「动作外」判断瓶颈在 Pass 内部还是验证器；
3. `算子×动作`：在相邻分组中判断同一算子是否被多条 Pattern 重复作用，用「算子合计」判断该算子的总代价；
4. `算子`：按「文件」「行」筛选，定位具体算子实例与源码行。

表格工具内二次统计：

- 数值列为真数值，可直接求和、排序或建立数据透视表；
- 时间字段已是秒，可直接参与运算；如需毫秒展示可增设辅助列，例如 `=F2*1000`；
- `Pass` 表的「选项」列可对照编译命令行选项定位管线配置。

多线程口径注意：

- `threads` 大于 1 时，各表行求和大于 `total_s`（线程并行执行），任何「占总耗时百分比」不可跨行相加，故占比分母切换为 `inside_actions_s`；
- 多线程运行时 `outside` 是各线程未覆盖时间的算术和，包含线程同步与空闲等待，不能解释为验证器开销；
- 需要加性分解数据时，编译时附加 `-mlir-disable-threading` 重新采集；控制台的「耗时构成」只在单线程采集下可直接与总耗时对照。

## 7. 与 `report.json` 的关系

- 两份产物同源生成、数值逐字段一致：自动化消费读取 `report.json`，人工分析读取 `report.xlsx`。
- 报告不含版本号字段；字段语义变更直接体现为本文档与 `docs/usage.md` 第 3 节的更新。
- JSON 字段规范见 `docs/usage.md` 第 3 节；指标解读规则见 `docs/measurement.md`；事件格式见 `docs/trace-format.md`。
